# 排查参考

当 `python analytics.py status` 不是 `ready`、计数异常，或实时数据不更新时读本文件。

先看 `status` 输出，再下结论。它会给出解析到的根路径、集成状态、历史扫描与实时写入时间，以及诊断信息。

## `status` 状态含义

| 取值 | 含义 | 处理 |
| --- | --- | --- |
| `ready` | 已发现且解析成功 | 无需处理 |
| `not_installed` | 未发现该平台数据目录 | 不是错误。仅当用户需要统计该平台时才安装 |
| `partial` | 部分文件失败 | 查看 `diagnostics`，重跑 `scan --platform <平台>` |
| `unsupported_version` | 会话格式无法识别 | 宿主改了格式。不要盲改代码，先如实反馈 |
| `integration_error` | 实时入口失败 | 重新安装该平台的集成 |

## 集成装不上

`integration_status` 为 `conflict`，表示本工具将要写入的位置已有文件，但不是本工具创建的。安装器刻意拒绝触碰它。

不要删除该文件。先向用户确认归属。若确认无关，由用户决定如何处理；若是本工具的旧副本，先比对内容，得到用户确认后再处理。

## Hook 已安装但没有数据

最常见原因是 Hook 未受信任。Codex 和 Claude Code 都会在用户批准前跳过 Hook：

- Codex：打开 `/hooks` 并信任对应条目。
- Claude Code：接受工作区信任提示。

若信任已完成，在真实使用一次 Skill 后检查 `last_realtime_at`。时间始终不推进，说明宿主没有投递事件。

同时确认检出没有被移动。已安装的 Hook 内嵌绝对路径。把宿主配置里记录的命令与当前检出位置对比，不一致就先卸载再从当前位置重装。

## 计数看起来不对

- **对话中用过的 Skill 没被记录。** 本工具只统计可观测的调用证据：结构化 Skill 工具调用、slash 命令，或对具体 `SKILL.md` 的真实读取。普通提及、Skill 清单、工具输出、路径搜索和存在性检查都不计数，这是有意设计。若宿主没有留下任何记录，本工具无法统计。
- **重扫后计数变少。** 通常是去重正确。一次调用由平台 + 会话 + 回合 + Skill 身份共同确定，重扫同一会话不会重复计数。
- **同名 Skill 分开显示。** 仪表盘按名称聚合展示，但底层保留各自身份。因此不同平台或不同路径下的同名 Skill 在原始数据中不会合并。

## 仪表盘问题

若仪表盘没有反映最新扫描，重新执行 `python analytics.py report`。报表是按需生成的，不是实时视图。

若找不到仪表盘文件，以 `report` 命令输出中的实际路径为准，不要假设默认位置。

## 数据位置

数据库、仪表盘和错误日志位于按用户划分的数据目录：

- Windows：`%LOCALAPPDATA%\skill-analytics\`
- macOS 与 Linux：`$XDG_DATA_HOME/skill-analytics/`，或 `~/.local/share/skill-analytics/`

可用 `SKILL_ANALYTICS_HOME` 覆盖。若存在旧版本的仓库内 `data/analytics.db`，首次访问数据库时会复制到用户数据目录一次，原文件保留。

除用户明确要求，不要删除该用户数据目录来“重置”任何内容，它包含全部历史。
